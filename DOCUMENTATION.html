Pure Java 21 Architecture

1. Executive Architecture Overview

TalentFlow is built as a college-viva-ready, production-quality Recruitment and Applicant Tracking System using Pure Core Java 21 without third-party frameworks. The system enforces tight encapsulation, dynamic ID auto-incrementing, permanent file-backed storage, and strict Role-Based Access Control (RBAC).

2. Complete File & Concept Mapping

🏗️ Model Layer (src/model/)

📄 User.java

  • Abstraction: Declared as an abstract class User. Serves as the base model for system actors and cannot be instantiated.
  • Abstract Method: Declares public abstract void displayDetails() forcing child classes to provide concrete display logic.
  • Encapsulation: Private fields (id, name, email, phone, password) protected behind public getters and setters.

📄 Candidate.java

  • Inheritance (extends): Extends User to inherit common profile fields.
  • Polymorphism (Method Overriding): Overrides displayDetails() and toString() to display candidate profile fields (skill, experience, status, resumeSummary).

📄 Recruiter.java

  • Inheritance (extends): Extends User to inherit common user fields.
  • Polymorphism (Method Overriding):** Overrides displayDetails() and toString() for recruiter attributes (company).

📄 Job.java

  • Encapsulation: Protects job posting properties (jobId, title, company, location, salaryRange, requiredSkill).
  • Constructor Overloading: Supports default vs custom salary range initialization.

📄 Application.java

  • Data Model: Links Candidate ID to Job ID with status workflow tracking (Applied, Interview, impulse Selected, Rejected, Withdrawn).

🗄️ Repository Layer (src/repository/)

📄 CandidateRepository.java

  • Repository Pattern: Decouples data access from business logic. Uses private static final ArrayList<Candidate>.
  • Static Initializer (static {}): Reads disk records from data/candidates.txt on system startup.
  • Dynamic Max-ID Auto-Increment: Method getNextId() calculates max(ID) + 1 (starting at 501), eliminating duplicate IDs.
  • Email Uniqueness: Method isEmailExists() prevents duplicate candidate email registrations.

📄 RecruiterRepository.java & JobRepository.java

  • Dynamic Max-ID Auto-Increment: Generates next unique Recruiter ID (starting at 1) and Job ID (starting at 101).
  • Static Disk Persistence: Automatically syncs changes to data/recruiters.txt and data/jobs.txt.

📄 ApplicationRepository.java

  • Dynamic Max-ID Auto-Increment: Generates unique Application ID (starting at 1001).
  • Cascade Deletion Integrity: Methods deleteApplicationsByCandidateId() and deleteApplicationsByJobId() clean up orphaned applications upon deletion.

⚙️ Service Layer (src/service/)

📄 CandidateService.java & JobService.java

  • Polymorphism (Method Overloading):** Implements overloaded search methods (searchCandidate(int) / searchCandidate(String) and searchJob(int) / searchJob(String)).
  • Privacy View Filtering: Method viewJobs() hides the REQUIRED SKILL column in public job views.

📄 ApplicationService.java

  • Automated Skill Matching Engine: Compares candidate skills against job requirements using string matching algorithms, auto-assigning eligible candidates.
  • Dual-Interface View: Renders separate applicant portals for Candidates vs Recruiters.

🛠️ Utility Layer (src/util/)

📄 Validation.java

  • Regular Expressions (Regex): Validates emails (strict domain format), 10-digit Indian phone numbers (starting with 6-9: ^[6-9][0-9]{9}$), and 8+ char complex passwords (upper, lower, digit, special char).

📄 FileManager.java

  • File I/O Streams: Uses BufferedReader, BufferedWriter, FileReader, and FileWriter.
  • Pipe Serialization & CSV Export: Manages custom disk persistence and exports system reports to data/ats_export_report.csv.

🖥️ Presentation Layer (src/menu/)

📄 Menu.java & Main.java

  • 4-Portal Role-Based Architecture: Manages Admin Portal (Password: admin_1234), Recruiter Portal (Password: Sarnine@123), Candidate Portal, and New Candidate Registration.
  • Exception Handling: Wraps console scanner loops in try-catch blocks to prevent crashes on invalid inputs.
